## 1. Общая архитектура

```
bot.py                  — основной файл, ~6200 строк
warmup_module.py        — модуль прогрева канала
nutrition_module.py     — дневник питания
calendar_module.py      — интеграция с Google Calendar
utils.py                — вспомогательные функции
```

**Стек:**
- Python 3 + aiogram 3.x (Telegram bot)
- Anthropic Claude API (OCR, анализ документов, генерация текстов)
- Google Sheets API (gspread) — основная база данных
- Google Calendar API — события
- Google Docs + Drive API — документы
- Notion API — инструкции и статьи
- Sber SaluteSpeech — распознавание голоса

**Доступ:**
- `ALLOWED_USERS = [7086707589, 469985712]` — кто может пользоваться ботом
- `NOTIFY_USERS = [469985712]` — кто получает напоминания календаря и утренний дайджест
- `NUTRITION_OWNER_USER_ID = 469985712` — питание только для одного пользователя

## 4. Финучёт

### ДДС (Таблица 1) и КУДиР (Таблица 2)

**Как работает:**
1. Пользователь нажимает "Таблица 1" или "Таблица 2"
2. Отправляет документы: фото чека, скрин из CRM, платёжку, PDF — любое количество
3. Нажимает "Обработать" (или пишет "готово")
4. Claude анализирует все документы разом → возвращает JSON
5. Бот показывает карточку с данными и кнопками редактирования
6. Данные записываются в Google Sheets

**Поддерживаемые типы документов:**
- Фото/скрин чека (ФД)
- Платёжное поручение (пп)
- СБП-оплата
- Комиссия банка
- Скрин из CRM (только как источник данных — не создаёт операцию)
- Выписка банка
- Возврат

**Автоопределение статьи расхода:**

## 5. Поиск гидов

**Базы данных гидов (3 таблицы):**

| База | Google Sheets ID | Листы | Структура столбцов |
|---|---|---|---|
| Новая база | `1xncgnaXSLIoDlV_...` | Все листы | country(0), city(1), name(2), contacts(3), desc(4) |
| Общая база | `1_euRreX-6seJQEh...` | Все листы | country(0), city(1), name(2), contacts(3), desc(4) |
| Гиды-компании | `1HdkRTK6W-NzTM2L...` | Все листы | name(0), city_country(1), contacts(2), desc(3), link(4) |

**Как работает поиск:**
1. Пользователь пишет: "Найди гида по Корее" / "Гиды по Дубаю"
2. `detect_guide_search()` извлекает поисковый запрос через regex
3. `search_guides_data(query)` перебирает все таблицы и все листы
4. `fuzzy_match(query, row_text)` — нечёткое сравнение по каждой строке
5. Результаты выводятся карточками по 10 штук

**Добавление гида:**
- Пользователь отправляет текст или фото с визиткой/контактами
- Claude извлекает: страна, город, имя, контакты, описание
- Записывается в "Новая база"

## 11. Прогрев

**Файл:** `warmup_module.py`

### Общий смысл
Анализирует статистику Telegram-канала за период прогрева:
- Читает скрины из раздела Statistics → Posts
- Считает охваты, лайки, репосты, вовлечённость
- Вместе с данными по продажам строит **donut chart** с % выполнения плана

### Меню прогрева
```
➕ Новый прогрев
📊 Добавить статистику
📈 Отчёт
📋 Данные по дням
👥 Обновить подписчиков    🗑 Сбросить дни
```

### Workflow

**1. Создание прогрева:**
- Название → план продаж (руб) → план продаж (шт) → кол-во подписчиков
- Создаётся уникальный ID (timestamp)

**2. Добавление статистики:**
- Пользователь отправляет скрины из Telegram Statistics (сколько угодно)
- Claude (Sonnet) читает каждый пост: дата, время, просмотры, лайки, репосты
- Дедупликация: если один пост виден на нескольких скринах — считается один раз (по дата+время)
- Для каждой даты показывает карточку подтверждения с тремя кнопками:

```
✅ Да, верно
✏️ Изменить
🗑 Удалить эту дату
```

- После подтверждения спрашивает продажи за эту дату: кол-во, сумма, комиссия

**3. Отчёт:**
- Генерирует PNG с donut chart (matplotlib)
- Левый бублик: % выполнения плана по деньгам
- Правые карточки: % по количеству, средний охват, вовлечённость
- Таблица последних 10 дней: посты, охват, вовлечённость, продажи, комиссия, % плана нарастающим итогом

### Структура таблицы "Прогрев_дни" (13 столбцов)
```
ID прогрева | Название прогрева | Дата | Постов | Сумма охватов | Ср.охват |
Лайки | Репосты | Вовлечённость% | Продажи шт | Продажи руб | Комиссия руб | % плана (нараст.)
```

### Формулы
- **Ср.охват** = Сумма просмотров / Постов
- **Вовлечённость%** = (Лайки + Репосты) / Постов / Подписчиков × 100
- **% плана** = Накопительная сумма продаж / План × 100

### State machine прогрева
```python
warmup_states[uid] = {
    "step": "new_name" | "new_plan_sum" | "new_plan_count" | "new_subscribers" |
            "collecting_photos" | "confirm_stats" | "confirm_stats_edit" |
            "day_sales_count" | "day_sales_sum" | "day_commission" | "upd_subscribers",
    "warmup_id": "20260607120000",
    "warmup_name": "Июнь 2026",
    "plan_sum": 150000.0,
    "plan_count": 10,
    "subscribers": 5000,
    "photos": [b"..."],
    "by_date": {"07.06.26": {"posts":5, "total_views":2500, "avg_views":500, "likes":120, "reposts":45}},
    "dates_queue": ["07.06.26", "08.06.26"],
    "days_entered": [{"date":"07.06.26", "posts":5, ...}]
```

## 15. Все промты

### 15.1 Разбор финансового документа (SYSTEM_PROMPT)
*Используется для: чеки, платёжки, СБП, комиссии, возвраты*
*Модель: Haiku | Max tokens: 1500*

Извлекает поля:
- `date` — дата платежа (строго из документа, не дата договора)
- `amount` — сумма в рублях (положительное число)
- `comment` — формат: "ФИО туриста, описание тура, договор XXX от ДД.ММ.ГГГГ"
- `order_number` — первый номер брони (KM..., MCC..., CBR..., IGR... или числовой)
- `note` — номер счёта/чека (не серийный номер ФН)
- `note_type` — "пп" (платёжка) или "ФД" (фискальный документ)
- `tour_operator_raw` — название оператора/плательщика
- `doc_type` — "чек|платежка|сбп|комиссия|crm|возврат|выписка|другое"
- `is_incoming` — true если деньги приходят нам
- `tour_month`, `tour_year` — даты тура если видны
- `is_refund` — true если возврат
- `bank_name` — банк где счёт ИП
- `crm_order_number` — номер заявки в CRM
- `crm_creation_date` — дата создания договора ДД.ММ.ГГГГ

**Ключевые правила:**
- Не выдумывать данные если их нет
- Валютные операции: amount = рублёвый эквивалент
- ФИО Малинкиной в comment НЕ писать (это мы сами)
- CRM-скрин = только источник данных, не создаёт операцию

### 15.2 Пакетный разбор (SYSTEM_PROMPT_BATCH)
*Используется для: несколько документов по одной брони*

Правила:

### 15.3 Извлечение данных гида (GUIDE_SYSTEM_PROMPT)

### 15.12 OCR скринов прогрева — ГЛАВНЫЙ ПРОМТ
*Модель: **Sonnet** (`claude-sonnet-4-6`) | Max tokens: 3000*
*Файл: warmup_module.py*

```
Перед тобой скриншоты раздела статистики Telegram-канала (Statistics → Posts).

ЗАДАЧА: для каждого поста выпиши 5 цифр. Потом сгруппируй по датам.

ШАГ 1 — читай каждый пост по одному сверху вниз:

Каждый пост выглядит так:
  [превью текста]   NNN просмотров
  ДД.ММ.ГГ в ЧЧ:ММ   ♡ N   ↩ N

Для каждого поста:
  - ВРЕМЯ: из строки "ДД.ММ.ГГ в ЧЧ:ММ" — только "ЧЧ:ММ"
  - ДАТА: из той же строки — только "ДД.ММ.ГГ"
  - ПРОСМОТРЫ: число перед словом "просмотров" или "views"
  - ЛАЙКИ: число после иконки-сердечка ♡. Если сердечка НЕТ → 0
  - РЕПОСТЫ: число после иконки-стрелки ↩. Если стрелки НЕТ → 0

ВАЖНО про иконки:
  - Иконка ♡ (сердечко) = ЛАЙКИ
  - Иконка ↩ (стрелка пересылки) = РЕПОСТЫ
  - Иконки могут ОТСУТСТВОВАТЬ — это значит 0, не придумывай числа
  - Порядок иконок: сначала ♡ лайки, потом ↩ репосты
  - Если видишь только одну иконку — определи по виду что это: сердечко или стрелка

ШАГ 2 — дедупликация:
  Если один и тот же пост (дата + время совпадают) встречается 
  на нескольких скринах — включи его ОДИН раз.

ШАГ 3 — верни JSON (ТОЛЬКО JSON, без текста вокруг):
{
  "посты": [
    {"дата": "ДД.ММ.ГГ", "время": "ЧЧ:ММ", "просмотры": ЧИСЛО, "лайки": ЧИСЛО, "репосты": ЧИСЛО}
  ],
  "по_датам": {
    "ДД.ММ.ГГ": {"постов": ЧИСЛО, "сумма_просмотров": ЧИСЛО, "лайки": ЧИСЛО, "репосты": ЧИСЛО}
  }
}

Лайки и репосты в "по_датам" — это СУММА соответствующих полей из "посты" для той же даты.
```

## 16. State machine

### Основной словарь состояний

```python
user_states[uid] = {
    "table": 1 | 2 | "subs" | "nutrition" | "guides" | "guide_search" |
             "travel" | "knowledge" | "tourists" | "tasks" | "media" |
             "instructions" | "personal" | "ideas",
    "step": "конкретный_шаг"
}
```

### Дополнительные словари

| Словарь | Для чего |
|---|---|
| `batch_docs[uid]` | Накопление документов до обработки |
| `guide_docs[uid]` | Документы по одному гиду |
| `tourist_docs[uid]` | Документы по одному туристу |
| `instructions_draft[uid]` | Черновик инструкции/статьи |
| `recreate_drafts[uid]` | Черновик при пересоздании |
| `pending_delete[uid]` | Строки подписок на удаление |
| `auth_sessions[uid]` | Timestamp последнего входа в менеджер паролей |
| `warmup_module.warmup_states[uid]` | Состояния прогрева |
| `nutrition_module.nutr_states[uid]` | Состояния питания |
| `calendar_module.cal_states[uid]` | Состояния календаря |

### Сброс всех состояний

При переходе в другой раздел вызывается `clear_all_states(uid)`, которая очищает **все** словари состояний включая модули — чтобы не было "утечки" состояний между разделами.
